<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    An online streaming portal generates 20,000 user clickstream events every second (page views, video scrubs, clicks). Storing raw JSON files directly on S3 resulted in millions of tiny 2KB files. Running a query across 1 day of data required scanning 1.7 Billion files, costing thousands of dollars per query and timing out Athena.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Near Real-Time Availability</strong>: Telemetry must be queryable via SQL within 60 seconds of emission.</li>
    <li><strong>Optimized Storage Format</strong>: Convert unstructured JSON to compressed columnar Apache Parquet.</li>
    <li><strong>Partition Pruning</strong>: Enable queries to scan only targeted date partitions (<code>year=YYYY/month=MM/day=DD/hour=HH</code>).</li>
  </ul>
</section>

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Data Lake Law:</strong> Athena charges purely based on the number of bytes scanned from S3. Using <strong>Apache Parquet + Date Partitioning</strong> is the single most effective way to cut big data query costs by 90%.
  </blockquote>
