<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    An electric vehicle manufacturer maintains a fleet of 500,000 connected cars worldwide. Every vehicle transmits 50 telemetry points (battery voltage, motor temperature, tire pressure, GPS coordinates) every 10 seconds over cellular networks. The legacy polling architecture suffered from dropped packets in tunnels and collapsed under 1.2 Billion daily telemetry messages.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Lightweight Cellular Protocol</strong>: Use standard MQTT over TLS with minimal bandwidth consumption.</li>
    <li><strong>Massive Scalability</strong>: Ingest up to 60,000 telemetry messages/second during rush hour peaks.</li>
    <li><strong>Time-Series Compression</strong>: Store 3 years of historical vehicle telemetry while keeping storage costs manageable.</li>
    <li><strong>Real-Time Collision / Critical Alerting</strong>: Trigger emergency dispatch in &lt; 3 seconds upon crash sensor trigger.</li>
  </ul>
</section>

<section id="architecture-overview">
  <h2>3. Architecture Overview & Data Flow</h2>
  
  <ArchitectureDiagram 
    title="Connected Fleet IoT Telemetry Architecture"
    diagram={`graph TD
    Vehicle([500,000 Connected Electric Vehicles]) -->|MQTT over TLS:8883 (X.509 Cert)| IoTCore[AWS IoT Core Message Broker]
    
    subgraph IoTRulesEngine [IoT Rules Engine Routing]
        IoTCore -->|SELECT * FROM 'vehicles/+/telemetry'| Kinesis[Amazon Kinesis Data Stream]
        IoTCore -->|SELECT * WHERE crash_detected = true| UrgentLambda[Emergency Dispatch Lambda]
    end

    UrgentLambda -->|Immediate Alert| SNS[Amazon SNS: First Responders]

    Kinesis --> TimestreamWriter[Lambda Batch Writer]
    TimestreamWriter --> Timestream[(Amazon Timestream: In-Memory & Magnetic Tiers)]
    
    Timestream --> SageMaker[SageMaker: Predictive Maintenance ML]

    style IoTCore fill:#18223B,stroke:#F97316,stroke-width:2px,color:#fff
    style Timestream fill:#0B101C,stroke:#38BDF8,stroke-width:2px,color:#fff
    style Kinesis fill:#101728,stroke:#E879F9,stroke-width:1px,color:#fff`}
  />

  <ol>
    <li><strong>Mutual TLS Authentication</strong>: Vehicles authenticate to AWS IoT Core using dedicated device X.509 certificates provisioned in factory HSM chips.</li>
    <li><strong>IoT SQL Rules Engine</strong>: Evaluates incoming JSON payloads and splits normal telemetry from urgent crash alerts.</li>
    <li><strong>Kinesis Buffer Stream</strong>: Buffers massive telemetry surges and batches writes to Amazon Timestream.</li>
    <li><strong>Tiered Time-Series Storage</strong>: Amazon Timestream stores the most recent 24 hours of data in ultra-fast in-memory storage, automatically transitioning older data to magnetic storage at 90% lower cost.</li>
  </ol>
</section>

```
-- IoT Rule to filter urgent battery overheating alerts
SELECT 
  topic(2) as vehicle_id, 
  battery_temp_celsius, 
  speed_kmh, 
  gps_lat, 
  gps_lon,
  timestamp() as received_at
FROM 'vehicles/+/telemetry'
WHERE battery_temp_celsius > 55.0
```

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>IoT Architecture Law:</strong> For connected devices, always decouple the device connection broker (AWS IoT Core) from the analytics storage engine (Amazon Timestream) using streaming buffers (Amazon Kinesis) to withstand cellular reconnect storms.
