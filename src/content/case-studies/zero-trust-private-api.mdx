<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    A digital bank was transferring 60 Terabytes of encrypted ledger data each month from private compute instances to Amazon S3 and DynamoDB. Because compute subnets used NAT Gateways to reach public AWS endpoints, they incurred over <strong>$2,700/month in NAT data processing fees ($0.045/GB)</strong>. Moreover, banking regulations required all network traffic to remain strictly within private network pathways.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Zero Public Internet Routing</strong>: Data between compute and AWS services (S3, DynamoDB, Secrets Manager, KMS) must never leave AWS private fiber.</li>
    <li><strong>Cost Optimization</strong>: Eliminate NAT Gateway data transfer surcharges.</li>
    <li><strong>Envelope Encryption</strong>: Enforce Customer Managed Keys (CMK) on all stored financial payloads.</li>
  </ul>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="VPC Gateway Endpoint Route Table Policy" badge="IaC Recipe">

```
resource "aws_vpc_endpoint" "s3_gateway" {
  vpc_id          = aws_vpc.main.id
  service_name    = "com.amazonaws.us-east-1.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids = [aws_route_table.private.id]

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "AllowOnlyOurLedgerBucket"
      Effect    = "Allow"
      Principal = "*"
      Action    = ["s3:GetObject", "s3:PutObject"]
      Resource  = "arn:aws:s3:::bank-ledger-records-prod/*"
    }]
  })
}
```
