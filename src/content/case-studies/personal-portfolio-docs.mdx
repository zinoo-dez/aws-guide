<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    An individual developer or open-source team wants to host technical documentation and a portfolio site. Traditional VPS hosting (e.g. EC2, DigitalOcean) requires managing OS security patches, SSH keys, Nginx configurations, and renewing Let's Encrypt certificates every 90 days.
  </p>
  <p>
    If a project goes viral on Hacker News or Reddit, a single virtual server frequently crashes from connection pool exhaustion.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Zero Maintenance</strong>: Zero operating systems or server processes to patch.</li>
    <li><strong>Global Performance</strong>: Sub-50ms Time to First Byte (TTFB) globally.</li>
    <li><strong>Budget Ceiling</strong>: Under $1.00 per month for baseline traffic.</li>
    <li><strong>Security</strong>: HTTPS enforcement with automated TLS certificate renewals.</li>
  </ul>
</section>

<section id="architecture-overview">
  <h2>3. Architecture Overview & Data Flow</h2>
  
  <ArchitectureDiagram 
    title="Global Serverless Static Distribution"
    diagram={`graph LR
    User([End User Browser]) -->|HTTPS:443 / TLS 1.3| R53[Amazon Route 53 DNS]
    R53 -->|Alias Record| CF[Amazon CloudFront CDN]
    CF -->|Cache Hit: Return in 15ms| User
    CF -->|Cache Miss: SigV4 Auth OAC| S3[(Amazon S3 Private Bucket)]
    ACM[AWS Certificate Manager] -.->|Auto-Renew TLS Cert| CF

    style CF fill:#18223B,stroke:#FF9900,stroke-width:2px,color:#fff
    style S3 fill:#101728,stroke:#38BDF8,stroke-width:1px,color:#fff
    style R53 fill:#101728,stroke:#818CF8,stroke-width:1px,color:#fff`}
  />

  <ol>
    <li><strong>DNS Query</strong>: User requests <code>docs.example.com</code>; Route 53 resolves to the closest CloudFront Edge PoP.</li>
    <li><strong>Edge Caching</strong>: CloudFront serves cached assets with gzip/brotli compression.</li>
    <li><strong>Origin Access Control (OAC)</strong>: On a cache miss, CloudFront signs the request with AWS SigV4 to read from the private S3 bucket. Direct public access to S3 is disabled.</li>
  </ol>
</section>

  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Best Practice:</strong> Always use CloudFront Origin Access Control (OAC) with S3 rather than legacy Origin Access Identity (OAI) to support all AWS regions and SSE-KMS encryption.
