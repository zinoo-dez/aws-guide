<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    An enterprise with 50 AWS accounts struggled to investigate security incidents. Audit logs were scattered across local CloudWatch log groups in different regions and accounts. When a security compromise occurred, gathering and correlating logs took over 4 hours, delaying threat containment.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Centralized Multi-Account Aggregation</strong>: Ingest CloudTrail and VPC Flow Logs into a dedicated Log Archive AWS account.</li>
    <li><strong>Tamper-Proof Immutability</strong>: Enforce S3 Object Lock in Compliance Mode to satisfy SOC2/HIPAA mandates.</li>
    <li><strong>Rapid Forensic Querying</strong>: Search billions of IP connection records with SQL in seconds.</li>
  </ul>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="Sample Athena Threat Hunting Query: Rejected Port Scans" badge="Forensic SQL">

```
SELECT srcaddr, dstaddr, dstport, protocol, count(*) as reject_count
FROM vpc_flow_logs_db.vpc_flow_logs
WHERE action = 'REJECT' 
  AND year = '2026' AND month = '08' AND day = '20'
GROUP BY srcaddr, dstaddr, dstport, protocol
ORDER BY reject_count DESC
LIMIT 50;
```

</DeepDiveAccordion>

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Security Rule:</strong> Always send security logs to a separate, isolated <strong>Log Archive Account</strong> with S3 Object Lock. A compromised developer account must never have permissions to erase audit traces.
  </blockquote>
