<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    A financial services web portal authenticates millions of active users. Every single API request requires validating the user's session token and permissions. Querying relational databases on every HTTP request introduced 40ms of latency per call and saturated database CPU.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Sub-Millisecond Token Validation</strong>: &lt; 1ms latency for session token checks.</li>
    <li><strong>Automatic Session Expiry</strong>: Expire idle sessions after 30 minutes using native TTL.</li>
    <li><strong>High Availability</strong>: Automatic Multi-AZ failover with zero manual intervention.</li>
  </ul>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="Redis Key Schema with Atomic TTL" badge="Data Design">

```
# Store session with 1800 second (30 minute) TTL
SET session:token_9847fae391 '{"user_id": "u_882", "roles": ["admin"], "mfa": true}' EX 1800

# Extend session TTL on active user interaction
EXPIRE session:token_9847fae391 1800
```

  <ul>
    <li><strong>API Latency</strong>: 38ms overall reduction across all authenticated endpoints.</li>

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Session Rule:</strong> Never hit persistent disk databases for request-level authentication checks. Always use in-memory caches like Redis with strict TTL expiration.
  </blockquote>
</section>
