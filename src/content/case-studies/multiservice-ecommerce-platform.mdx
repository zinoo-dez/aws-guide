<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    A global retail conglomerate runs 80 distinct microservices written in Go, Java, Python, and Node.js. Their legacy Kubernetes setup used standard Cluster Autoscaler with fixed Node Groups. When traffic surged, provisioning new EC2 nodes took over 6 minutes, causing pending pods to stall and requests to drop.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Sub-60s Autoscaling</strong>: Scale nodes from 20 to 150 instances dynamically in under 1 minute.</li>
    <li><strong>Right-Sizing & Mixed Fleets</strong>: Intelligently select the cheapest available EC2 instance family (Graviton, x86, Spot, On-Demand) matching exact pod CPU/memory requirements.</li>
    <li><strong>Granular Pod Security</strong>: Zero shared node-level AWS IAM credentials (enforce IRSA).</li>
  </ul>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="Karpenter NodePool CRD Configuration" badge="Kubernetes Manifest">

```
apiVersion: karpenter.sh/v1beta1
kind: NodePool
metadata:
  name: default
spec:
  template:
    spec:
      requirements:
        - key: "karpenter.sh/capacity-type"
          operator: In
          values: ["spot", "on-demand"]
        - key: "kubernetes.io/arch"
          operator: In
          values: ["arm64", "amd64"]
        - key: "karpenter.k8s.aws/instance-category"
          operator: In
          values: ["c", "m", "r"]
      nodeClassRef:
        name: default
  disruption:
    consolidationPolicy: WhenUnderutilized
    expireAfter: 720h
```

</DeepDiveAccordion>
