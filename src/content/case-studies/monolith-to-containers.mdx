<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    A fintech SaaS company maintained a 10-year-old monolithic Rails application. Deploying a minor bug fix to the authentication code required re-testing and deploying the entire 2-gigabyte codebase. A single memory leak in the billing module crashed the entire customer-facing platform.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Zero-Risk Migration</strong>: Avoid a high-risk "Big Bang" rewrite; incrementally strangle features out of the monolith.</li>
    <li><strong>No Server Maintenance</strong>: The team had no dedicated Kubernetes/SRE engineers and needed serverless container management.</li>
    <li><strong>Path-Based Ingress</strong>: Transparently route traffic between legacy monolith and new microservices without breaking API URLs.</li>
  </ul>
</section>

<section id="architecture-overview">
  <h2>3. Architecture Overview & Data Flow</h2>
  
  <ArchitectureDiagram 
    title="Strangler Fig Migration Topology on ECS Fargate"
    diagram={`graph TD

        ALB -->|"/api/notifications/*"| NotifFargate[Notification Microservice - Fargate Task]
    end

    ECR[(Amazon ECR Container Registry)] -.->|"Pull Images"| AuthFargate
    ECR -.->|"Pull Images"| PayFargate
    
    CloudMap[AWS Cloud Map Private DNS] -.->|"Service Discovery"| PayFargate

  />

  <ol>
    <li><strong>Identify Boundary</strong>: Isolated the <code>/api/auth</code> domain as the first candidate for extraction.</li>
    <li><strong>Build Containerized Service</strong>: Packaged the new lightweight Node.js/Go service into a Docker image and pushed to Amazon ECR.</li>
    <li><strong>Deploy to ECS Fargate</strong>: Created an ECS Service with Target Tracking autoscaling (50% CPU).</li>
    <li><strong>Shift ALB Rule</strong>: Updated the ALB listener rule to route <code>/api/auth/*</code> to the Fargate Target Group while keeping all other traffic on the legacy monolith.</li>
  </ol>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="ALB Listener Rule Path Routing Pattern" badge="Terraform">

```
resource "aws_lb_listener_rule" "auth_microservice" {
  listener_arn = aws_lb_listener.front_end.arn
  priority     = 10

  action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.auth_fargate.arn
  }

  condition {
    path_pattern {
      values = ["/api/auth/*", "/oauth/*"]
    }
  }
}
```

</DeepDiveAccordion>
</section>

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Strangler Fig Law:</strong> Never attempt a 100% ground-up rewrite of a production monolith. Use ALB path routing and containerized Fargate tasks to extract one domain at a time.
  </blockquote>
