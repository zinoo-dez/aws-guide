<section id="business-problem">
  <h2>1. Business Problem & Context</h2>
  <p>
    An e-commerce marketplace receives over 200,000 product image uploads each day from sellers. The legacy system processed uploads synchronously on web servers, which caused HTTP request timeouts (504 Gateway Timeout) whenever sellers uploaded 20MB RAW or PNG files, leading to abandoned listings.
  </p>
</section>

<section id="requirements-constraints">
  <h2>2. Requirements & Constraints</h2>
  <ul>
    <li><strong>Asynchronous Decoupling</strong>: User upload completes in &lt;500ms; background processing runs asynchronously.</li>
    <li><strong>Generate Multiple Tiers</strong>: WebP thumbnails (150x150), medium cards (600x600), and zoom views (1600x1600).</li>
    <li><strong>Zero Server Management</strong>: Scale from 0 at night to 5,000 concurrent transformations during flash sales.</li>
  </ul>
</section>

<section id="architecture-overview">
  <h2>3. Architecture Overview & Data Flow</h2>
  
  <ArchitectureDiagram 
    title="Event-Driven Media Pipeline Topology"
    diagram={`graph LR
    User([Seller Web/Mobile App]) -->|1. Direct Upload via Pre-Signed URL| S3Upload[(S3 Raw Uploads Bucket)]
    S3Upload -->|2. S3 ObjectCreated Event| EB[Amazon EventBridge]
    EB -->|3. Filter: *.jpg / *.png| SQS[Amazon SQS Queue]
    SQS -->|4. Batch Trigger| Lambda[AWS Lambda: Sharp Image Worker]
    Lambda -->|5. Save WebP Thumbnails| S3Processed[(S3 Optimized Delivery Bucket)]
    Lambda -->|6. Publish Event| EB_Out[EventBridge: ImageOptimized]

    style S3Upload fill:#101728,stroke:#FF9900,stroke-width:1px,color:#fff
    style EB fill:#18223B,stroke:#F59E0B,stroke-width:2px,color:#fff
    style Lambda fill:#18223B,stroke:#A78BFA,stroke-width:2px,color:#fff
    style S3Processed fill:#101728,stroke:#38BDF8,stroke-width:1px,color:#fff`}
  />

  <ol>
    <li><strong>Direct Pre-Signed URL Upload</strong>: The client requests a temporary S3 pre-signed PUT URL from the backend API, bypassing backend application servers entirely for upload bandwidth.</li>
    <li><strong>EventBridge Notification</strong>: S3 emits an <code>ObjectCreated</code> event directly to Amazon EventBridge.</li>
    <li><strong>SQS Buffering</strong>: EventBridge pushes the event into an SQS queue to protect downstream database writes and rate-limit third-party APIs.</li>
    <li><strong>Lambda Transformation</strong>: Lambda functions read SQS batches, download the source image, generate WebP variants using libvips/Sharp, and save them to the public CDN bucket.</li>
  </ol>
</section>

<section id="implementation">
  <h2>6. Implementation Highlights</h2>
  <DeepDiveAccordion title="Optimizing Lambda Memory for CPU-Intensive Sharp Resizing" badge="Performance Tuning">
    <p>
      AWS Lambda allocates vCPU proportionally to configured memory. While image resizing requires ~150MB of RAM, configuring Lambda with <strong>1769MB (1 full dedicated vCPU)</strong> drops execution time from 2,400ms down to 650ms.
    </p>
    <p>
      Because Lambda charges <code>Gigabyte-Seconds</code>, running a faster 1769MB function actually costs <strong>less money</strong> than running a slow 512MB function.
    </p>
  </DeepDiveAccordion>
</section>

<section id="results-metrics">
  <h2>7. Results & Key Metrics</h2>
  <ul>
    <li><strong>Client Upload Time</strong>: Reduced from 8.2s to <strong>450ms</strong> via direct S3 pre-signed URLs.</li>
    <li><strong>Cost</strong>: 200,000 daily transformations cost just <strong>$1.15 per day</strong> on AWS Lambda.</li>
  </ul>
</section>

<section id="takeaways">
  <h2>8. Key Architectural Takeaways</h2>
  <blockquote>
    <strong>Media Ingestion Rule:</strong> Never route multi-megabyte file uploads through your API servers. Always issue S3 Pre-Signed URLs and process events asynchronously.
  </blockquote>
</section>
